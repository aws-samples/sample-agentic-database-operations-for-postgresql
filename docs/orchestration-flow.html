HARD GATE — cannot call any specialist. Its only move is recommend_investigation, which offers "Start investigation". No checking first, no numbers before the offer. If no symptom was named at all, it may first ask the operator ONE clarifying question with symptom options (still no tools); the reply keeps the diagnosis intent.

What's in the system

Reference only, not part of the flow above.

AGENTS

2 supervisors: Orchestrator (chat) and Investigation agent.

3 specialists, shared as delegation targets by both supervisors:

  • PostgreSQL, 52 structured read-only tools
  • Observability, 17 tools, CloudWatch / Performance Insights / CloudTrail / logs
  • Research (docs_agent), web search plus trusted-page fetch

1 agent outside both supervisors:

  • Learning, 1 tool (Research). Trend analysis. Invoked by the scan pipeline, not reachable from chat or an investigation.

Supervisors stay small and delegate; the heavy tool sets live on the specialists.

RUNBOOKS (SOPs)

7 files. The accuracy and safety guardrails are always in both system prompts.

An investigation loads 4 via get_runbooks: protocol, diagnostics, data-source rules, and one engine guide (Aurora or RDS, never both).

Chat loads 2: the engine guide and data-source rules. No RCA protocol.

SKILLS

32 total, 9 of them available in chat.

Each is a folder with a SKILL.md: frontmatter declaring name, description, allowed tools and which surface it appears on, then the procedure in the body.

Exactly one loads per investigation, and only when needed.

CHECKS AND THRESHOLDS

registry.yaml, 51 checks with their curated symptom triggers and the skill each maps to.

references.yaml, severity threshold bands for the same 51 checks.
